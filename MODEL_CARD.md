# Model Card: AI Aquaculture Guardian Forecasting & Anomaly Engines

---

## 1. Model Details

- **Model Name**: Multi-Step Water Quality Forecaster (`ForecastingEngine`) & Hybrid Anomaly Detector (`AnomalyDetector`)
- **Version**: 2.0.0 (Competition Edition)
- **Model Architecture**:
  - **Forecasting**: Random Forest Regressor (`sklearn.ensemble.RandomForestRegressor`) with Recursive Multi-step Strategy
  - **Anomaly Detection**: Hybrid Statistical Rolling Z-Score ($W=30, Z_{\text{thresh}}=2.5$) + Isolation Forest (`sklearn.ensemble.IsolationForest`, contamination=0.05) + Stuck Sensor Heuristic
  - **Inference Runtime**: Standard scikit-learn with OpenVINO™ ONNX export abstraction (`edge/inference_engine.py`)
- **License**: MIT
- **Target Domain**: Inland and coastal aquaculture pond monitoring (shrimp, catfish, pangasius).

---

## 2. Intended Use & Limitations

### Intended Use
- **Primary Use**: Early warning decision-support for fish/shrimp pond operators by forecasting pH trends 5–30 steps ahead.
- **Intended Users**: Farm managers, aquaculture technicians, research teams.

### Out-of-Scope & Limitations
- **NOT an Automated Dosing System**: The model must never directly trigger automated chemical dosage (e.g. lime or acid pumps) without human verification.
- **Single-Parameter Initial Scope**: Current demo is focused on pH. Real ponds require multi-sensor correlation (pH, DO, Temperature, Salinity, Ammonia).
- **Synthetic Training Data**: All current performance metrics are evaluated on simulated data generated by `simulator/ph_simulator.py`. Real-world calibration is required before physical farm deployment.

## 3. Feature Engineering ($11$ Dimensional Vector)

Features are computed using **strictly past observation history** ($t \le \text{now}$) to prevent data leakage:

| Feature Index | Name | Formula / Description |
|---|---|---|
| 0 | `current_value` | Latest observed pH ($x_t$) |
| 1 | `rolling_mean` | $\mu = \frac{1}{W} \sum_{i=0}^{W-1} x_{t-i}$ ($W=20$) |
| 2 | `rolling_std` | $\sigma = \sqrt{\frac{1}{W} \sum (x_{t-i} - \mu)^2}$ |
| 3 | `rolling_min` | $\min_{0 \le i < W} x_{t-i}$ |
| 4 | `rolling_max` | $\max_{0 \le i < W} x_{t-i}$ |
| 5 | `trend` | Least-squares linear regression slope $\beta_1$ over window $W$ |
| 6 | `rate_of_change` | First difference: $x_t - x_{t-1}$ |
| 7 | `recent_delta` | Window net change: $x_t - x_{t-W+1}$ |
| 8 | `acceleration` | Second difference: $(x_t - x_{t-1}) - (x_{t-1} - x_{t-2})$ |
| 9 | `hour_sin` | Cyclical time encoding: $\sin(2\pi \cdot \text{hour} / 24)$ |
| 10 | `hour_cos` | Cyclical time encoding: $\cos(2\pi \cdot \text{hour} / 24)$ |

## 5. Edge AI & Hardware Acceleration (Intel® OpenVINO™)

- **Test Machine**: Windows 11 PC (Host CPU)
- **Frameworks**: `openvino==2026.3.0`, `skl2onnx==1.20.0`, `onnx==1.21.0`
- **Current Technical Finding**:
  - `skl2onnx` converts `RandomForestRegressor` to ONNX operators including `ai.onnx.ml.TreeEnsembleRegressor`.
  - OpenVINO's ONNX frontend does not yet provide a native translator for `TreeEnsembleRegressor` in standard CPU IR pipelines.
  - **Honest Handling**: The `OpenVINOInferenceEngine` detects this conversion error at initialization and seamlessly falls back to `SklearnInferenceEngine`, ensuring zero disruption and accurate reporting.
  - **Measured CPU Latency**:
    - P50: ~19.2 ms
    - P95: ~20.2 ms
    - Throughput: ~51 inferences/second (sufficient for real-time sensor streams running every 1–5 seconds).
